# КТ № 8. Контрольные вопросы

1. **Для чего нужны модульные тесты?** Они проверяют поведение отдельной функции или класса и дают быструю обратную связь при изменениях. В этой работе тесты Petstore интеграционные, поскольку вызывают внешний API.
2. **Чем NUnit отличается от xUnit?** NUnit использует `[Test]`, `[TestCase]` и методы `[SetUp]` / `[TearDown]`. В xUnit применяются `[Fact]`, `[Theory]`, конструктор, `IDisposable` или `IAsyncLifetime` и общие фикстуры. По умолчанию xUnit создаёт экземпляр тестового класса на каждый тест, NUnit использует один экземпляр фикстуры, если не задан другой жизненный цикл.
3. **Что такое параметризация?** Повторное выполнение одного тестового сценария с разными наборами входных данных. Каждый набор получает собственный результат.
4. **Зачем нужны фикстуры?** Они подготавливают данные и ресурсы перед тестом и освобождают их после него. Область действия определяет, когда фикстура создаётся повторно.
5. **Зачем проверять репозитории данных?** Проверки показывают, что запросы корректно читают, сохраняют и обновляют записи, а ограничения и транзакции работают на используемом движке БД.
6. **Как запустить тесты .NET?** `dotnet test` запускает тесты проекта из терминала. Для этих прогонов использован PowerShell, выбранная IDE для работы с проектом — Visual Studio Code. В IDE можно открыть терминал и выполнить ту же команду.
7. **Что общего между pytest и xUnit?** Оба обнаруживают тесты, выполняют их отдельно, поддерживают параметризацию и подготовку ресурсов и показывают причину падения.
8. **В чём преимущества pytest?** Достаточно обычного `assert`, фикстуры передаются по имени аргумента и могут зависеть друг от друга, а плагины добавляют асинхронность, покрытие и отчёты.
9. **Для чего может пригодиться Expecto?** Для F#-проектов, где удобно описывать тесты списками и функциями, применять `async` и проверять свойства через FsCheck.
